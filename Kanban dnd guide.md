# Канбан-доска с Drag & Drop на Next.js — пошаговое руководство

Это не туториал с готовым кодом. Здесь для каждого этапа: **что должно получиться**, **как проверить, что готово**, **какие API нужны** и **на чём ты споткнёшься**. Код пишешь ты.

---

## Правила игры

1. **Не гуглить готовую реализацию канбана.** Гуглить отдельные API (`dataTransfer`, `getBoundingClientRect`) — можно и нужно.
2. **Один этап = один коммит.** Название коммита — номер этапа. Так ты увидишь свой прогресс, а если сломаешь — откатишься.
3. **Перед каждым этапом пиши прогноз** в файл `NOTES.md`: что сделаешь, где ожидаешь сложность, сколько времени займёт. После этапа возвращайся и дописывай, что вышло на самом деле. Это и есть тренировка «мыслить наперёд» — без сравнения прогноза с фактом навык не растёт.
4. **Библиотеку DnD не подключаем до этапа 11.** Сначала руками через нативный HTML5 Drag and Drop API. Иначе ты выучишь не DnD, а конкретную библиотеку.
5. Если застрял больше чем на 40 минут — не сиди. Загугли конкретный симптом («drop event not firing»), а не задачу целиком.

## Этап 0. Каркас проекта

**Цель:** пустая страница с доской, которая рендерится без ошибок.

**Что сделать**

- Создай `app/board/page.tsx` (или переиспользуй главную).
- Создай папку `components/board/`.
- Проверь, что стили работают (Tailwind или CSS-модули — что стоит в проекте).

**Ключевой момент Next.js.** App Router рендерит всё на сервере по умолчанию. Компонент с `useState` или обработчиками событий обязан начинаться с `"use client"` в первой строке файла. Ошибку «You're importing a component that needs useState» ты увидишь минимум один раз — это нормально.

Хорошая практика с самого начала: `page.tsx` оставь серверным, а внутрь него положи `<Board />` — клиентский компонент. Так клиентским станет только то, что реально интерактивно.

**Готово, когда:** страница открывается, в консоли пусто.

## Этап 1. Модель данных (самый важный этап)

**Цель:** решить, как хранится состояние. Ни строчки JSX.

Открой `NOTES.md` и опиши структуру. У тебя два варианта:

**Вариант A — вложенный**

```
columns: [
  { id, title, tasks: [ {id, text}, ... ] },
  ...
]
```

**Вариант B — нормализованный**

```
tasks:   { [taskId]: {id, text} }
columns: [ { id, title, taskIds: [...] }, ... ]
```

**Задание.** Для каждого варианта распиши, как будет выглядеть операция «переместить задачу X из колонки 1 в колонку 3 на позицию 2». Напиши псевдокод обеих. Какой короче? Какой сломается, если задач станет 5000? Какой проще сериализовать в localStorage?

Выбери и **запиши в заметки, почему**. Через неделю, когда упрёшься в ограничение, вернёшься и увидишь, что именно не предусмотрел. Это ценнее, чем «выбрать правильно» с первого раза.

**Типы.** Опиши `Task`, `Column`, `BoardState` в `types.ts` до того, как писать компоненты. TypeScript тут работает как проектирование, а не как проверка.

**Готово, когда:** типы описаны, псевдокод перемещения написан, выбор обоснован.

## Этап 2. Статичная доска

**Цель:** три колонки с захардкоженными задачами на экране. Ничего не кликается.

- Начальное состояние — константа в файле, три колонки: «В работе», «Выполнено», «Отклонено».
- Компоненты: `Board` → `Column` → `TaskCard`. Не больше.
- Раскладка: flex-контейнер по горизонтали, колонки одинаковой ширины, внутри вертикальный список с прокруткой.

**Ловушка.** Не выноси задачу в `useMemo`, не делай абстракций «на будущее». Три компонента, максимально тупо. Абстракции появятся сами на этапе 11, когда станет больно.

**Готово, когда:** видно три колонки с карточками, вёрстка не разъезжается при добавлении 20 карточек в одну колонку.

## Этап 3. Добавление задач

**Цель:** в каждой колонке поле ввода, задача добавляется в конец списка.

**Что понадобится**

- `useState` для состояния доски — подними его в `Board`, а не в `Column`. Колонки должны получать данные и колбэки пропсами.
- Контролируемый инпут в каждой колонке (у каждой своё локальное состояние текста).
- Генерация id: `crypto.randomUUID()`.

**Ловушка Next.js.** Никогда не вызывай `crypto.randomUUID()`, `Date.now()` или `Math.random()` во время рендера — сервер и клиент сгенерируют разное, получишь hydration mismatch. Вызывай только внутри обработчика события или `useEffect`.

**Ловушка иммутабельности.** `state.columns[0].tasks.push(task)` не вызовет ререндер и испортит данные. Нужно вернуть новый массив колонок, где новый объект только у изменённой колонки. Напиши эту функцию отдельно от компонента — потом переиспользуешь для перемещения.

**Самопроверка.** Умеешь ли ты обновить одно поле в объекте внутри массива внутри объекта, не мутируя ничего? Если сомневаешься — это ровно тот навык, который у тебя «забылся», и на этапе 7 он понадобится в трёх местах сразу.

**Готово, когда:** задачи добавляются во все три колонки, Enter работает как кнопка, пустая строка не добавляется.

## Этап 4. Удаление и редактирование

**Цель:** крестик на карточке удаляет задачу, двойной клик даёт отредактировать текст.

Это разминка перед DnD: те же иммутабельные обновления, но операции разные. Если этап 3 дался тяжело — задержись здесь, повтори.

**Ловушка.** При редактировании фокус должен уходить в инпут автоматически (`autoFocus` или `ref.current.focus()`), а Escape — отменять правку. Мелочь, но именно из таких мелочей состоит ощущение «сделано нормально».

## Этап 5. Сохранение в localStorage

**Цель:** после F5 доска остаётся такой же.

**Главная ловушка Next.js и одновременно главный урок этого этапа.** На сервере нет `window` и нет `localStorage`. Если прочитать их в инициализаторе `useState`, приложение упадёт при серверном рендере. Если прочитать в `useEffect` — первый кадр отрендерится с пустой доской, и пользователь увидит мигание.

Разберись, как это решают:

- чтение в `useEffect` + флаг `isLoaded`, до загрузки рендерим скелетон;
- либо динамический импорт доски с `ssr: false`.

Попробуй первый способ. Он честнее и объясняет тебе, что вообще происходит с гидратацией.

**Запись.** Отдельный `useEffect` с зависимостью от состояния доски. Подумай, не стоит ли добавить debounce, и запиши в заметки, почему решил так или иначе.

**Готово, когда:** перезагрузка сохраняет доску, в консоли нет warning про hydration.

## Этап 6. Нативный DnD: минимальный скелет

Дальше — суть. Читай внимательно, здесь три классические ловушки подряд.

**Цель:** карточка перетаскивается, при отпускании над колонкой в консоль печатается `id задачи → id колонки`. Состояние ещё не меняем.

**API, которое нужно**

На карточке:

- атрибут `draggable` — без него элемент просто не потащится;
- `onDragStart(e)` — здесь ты кладёшь id задачи: `e.dataTransfer.setData("text/plain", task.id)`. Ещё выставь `e.dataTransfer.effectAllowed = "move"`.
- `onDragEnd(e)` — сработает всегда, даже при отмене. Место для сброса визуальных состояний.

На колонке:

- `onDragOver(e)` — **обязательно `e.preventDefault()`**. Иначе браузер считает элемент запрещённой зоной, и `onDrop` никогда не выстрелит. Это ловушка №1 и причина 90% вопросов «drop не работает».
- `onDrop(e)` — тоже `e.preventDefault()`, затем `e.dataTransfer.getData("text/plain")`.

**Ловушка №2.** Внутри `dragover` метод `getData()` возвращает пустую строку — браузер прячет данные до момента дропа из соображений безопасности. Поэтому если тебе нужно знать _что_ тащат, чтобы подсветить колонку, — храни это в отдельном состоянии (`draggingTaskId`), которое ты сам выставил в `dragStart`. Через `dataTransfer` во время движения ты это не получишь.

**Ловушка №3.** Если внутри карточки есть инпут или кнопка, они могут перехватывать drag. Разберись с этим, когда столкнёшься.

**Готово, когда:** в консоли при каждом дропе печатается верная пара id.

## Этап 7. Перемещение между колонками

**Цель:** задача реально переезжает в другую колонку и падает в конец списка.

Вся работа — одна чистая функция:

```
moveTask(state, taskId, targetColumnId) -> newState
```

Напиши её вне компонента, в `lib/board.ts`. Она должна:

1. найти исходную колонку;
2. если исходная и целевая совпадают — вернуть состояние как есть (не создавай новый объект зря);
3. удалить задачу из исходной, добавить в целевую, вернуть новый `state`.

**Проверь эти случаи руками:**

- перетащить в ту же колонку, откуда взял;
- перетащить и отпустить за пределами доски;
- перетащить на саму карточку, а не на пустое место колонки (событие всплывёт — сработает ли обработчик колонки?);
- перетащить последнюю задачу из колонки, оставив её пустой (не схлопывается ли колонка в ноль высоты? нужен `min-height`).

**Готово, когда:** все четыре случая ведут себя предсказуемо, состояние не ломается.

## Этап 8. Подсветка зоны дропа

**Цель:** колонка, над которой висит курсор, визуально выделяется. При выходе — гаснет.

Тебе кажется, что это `onDragEnter` → подсветить, `onDragLeave` → погасить. Попробуй так и посмотри, что произойдёт.

**Ловушка.** `dragleave` срабатывает каждый раз, когда курсор переходит на дочерний элемент колонки. Подсветка будет мигать как гирлянда. Два способа решения:

- счётчик входов/выходов (`enterCount`), гасим только когда дошёл до нуля;
- проверка `e.relatedTarget` — ушёл ли курсор за пределы `e.currentTarget` (`currentTarget.contains(relatedTarget)`).

Реализуй любой, но **сначала честно воспроизведи баг**. Увидеть мигание своими глазами полезнее, чем прочитать про него.

**Дополнительно:** приглуши исходную карточку, пока её тащат (`opacity: 0.4` по `draggingTaskId`). Не через `onDragStart` напрямую в стиль элемента — Chrome сделает снимок элемента для «призрака» уже с новым стилем, и ты будешь таскать призрак-невидимку. Обойти можно через `setTimeout(..., 0)` или `requestAnimationFrame`. Разберись, почему.

## Этап 9. Сортировка внутри колонки

Самый алгоритмически интересный этап. Здесь появляется настоящая логика.

**Цель:** задача вставляется не в конец, а туда, где висит курсор, и между карточками видно линию-индикатор.

**Задача:** по координате курсора определить индекс вставки.

Подумай сам, прежде чем читать дальше. Что у тебя есть? Позиция курсора (`e.clientY`) и позиции всех карточек в колонке (`element.getBoundingClientRect()` даёт `top`, `bottom`, `height`).

<details>
<summary>Подсказка, если застрял на 20 минут</summary>

Для каждой карточки посчитай её вертикальную середину. Индекс вставки — это количество карточек, чья середина выше курсора. То есть: пройди по карточкам и найди первую, чья середина ниже курсора; её индекс и есть искомый. Если такой нет — вставляем в конец.

</details>

**Как получить DOM-узлы карточек.** Два пути: `useRef` с массивом рефов, или `data-`атрибуты + `querySelectorAll` по контейнеру. Второй проще, первый «правильнее». Выбери и запиши почему.

**Ловушка индексов.** Если ты перетаскиваешь карточку внутри той же колонки сверху вниз, то после удаления её из массива все индексы ниже сдвигаются на единицу. Вставка по «сырому» индексу окажется на позицию выше, чем ты ожидал. Проверь это на бумаге до того, как писать код: колонка `[A, B, C, D]`, тащим `A` на позицию между `C` и `D`. Какой индекс даст твоя функция? Какой нужен на самом деле?

**Индикатор.** Рисуй линию как отдельный элемент по вычисленному индексу, а не как `border-top` у карточки — иначе вёрстка будет прыгать на 2 пикселя при каждом движении.

**Готово, когда:** карточка встаёт ровно туда, где была линия. Включая случай перетаскивания вниз внутри одной колонки.

**Цель:** маленький блок в углу экрана, показывающий текущее DnD-состояние: что тащим, над какой колонкой, какой индекс вставки.

## Этап 11. Рефакторинг

К этому моменту `Board` разросся. Теперь — и только теперь — наводим порядок.

**Что вынести**

- Всю чистую логику (`moveTask`, `reorderTask`, `addTask`, `removeTask`) — в `lib/board.ts`. Никакого React внутри.
- Состояние доски — в `useReducer` вместо россыпи `useState`. Экшены: `ADD_TASK`, `MOVE_TASK`, `REMOVE_TASK`. Это ровно тот момент, когда `useReducer` становится очевидно лучше, а не «потому что так пишут в статьях».
- DnD-состояние — в кастомный хук `useDragAndDrop`, который возвращает пропсы для карточки и для колонки.

**Проверка качества рефакторинга:** функции из `lib/board.ts` должны тестироваться без рендера компонентов. Напиши три-четыре теста (Vitest или Jest). Если для теста нужен браузер — логика ещё не отделена от UI.

## Этап 12. Тач-устройства

Открой доску с телефона. Ничего не перетаскивается.

Нативный HTML5 Drag and Drop **не работает на тач-устройствах**. Это не баг твоего кода — это ограничение API. Именно поэтому существуют библиотеки.

**Варианты:**

- переписать на Pointer Events (`pointerdown`/`pointermove`/`pointerup` + `setPointerCapture`) — сложно, но ты будешь понимать всё до конца;
- взять **`@dnd-kit`** — построена на pointer events, поддерживает клавиатуру и скринридеры, живая;
- `react-beautiful-dnd` — не бери, разработка прекращена.

**Важно:** переходи на библиотеку только сейчас. Ты уже знаешь, что она делает под капотом, поэтому её абстракции (`DndContext`, `useDraggable`, `useDroppable`, коллизии, сенсоры) лягут на понимание, а не заменят его. Сравни свою реализацию с их API и запиши в заметки, где ты решил задачу иначе и почему.

## Если хочется дальше

По возрастанию сложности:

1. **Фильтр и поиск** по задачам — простое, но заставит подумать про производные данные.
2. **Undo/Redo** (Ctrl+Z). Стек прошлых состояний. Легко, пока не задумаешься, что класть в стек — состояния целиком или обратные операции. Оба варианта имеют смысл, выбор надо обосновать.
3. **Клавиатурная доступность.** Взять карточку на Space, двигать стрелками, отпустить на Enter, объявлять изменения через `aria-live`. Мало кто это умеет, и это заметно выделяет на собеседовании.
4. **Мультиперетаскивание.** Выделить несколько карточек с Shift и потащить пачкой. Сильно сложнее, чем кажется.
5. **Синхронизация между вкладками** через `BroadcastChannel` или событие `storage`.
6. **Бэкенд** на Route Handlers + оптимистичное обновление UI: карточка переезжает мгновенно, запрос уходит фоном, при ошибке — откат.

## Диагностика частых проблем

| Симптом                              | Где искать                                                               |
| ------------------------------------ | ------------------------------------------------------------------------ |
| `onDrop` не вызывается               | Нет `e.preventDefault()` в `onDragOver`                                  |
| `getData()` пустой во время движения | Так и задумано, храни id в своём state                                   |
| Подсветка мигает                     | `dragleave` от дочерних элементов, нужен счётчик                         |
| Карточка не тащится                  | Забыт атрибут `draggable`                                                |
| «Призрак» невидимый                  | Стиль применён синхронно в `dragStart`, отложи через `setTimeout(...,0)` |
| `useState is not a function`         | Забыт `"use client"`                                                     |
| Text content did not match           | `Date.now()`/`random()`/`localStorage` во время рендера                  |
| Не работает на телефоне              | Ограничение HTML5 DnD, см. этап 12                                       |
| Список «прыгает» при наведении       | Индикатор меняет размеры соседей, рисуй его абсолютно                    |
